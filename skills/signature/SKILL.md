# Signature

Builds the one signature line that marks AI-generated text. The user in the signature is always the currently logged-in GitHub CLI user, so nobody has to set anything up.

## Requirements

| Requirement | Needed for | Check |
| --- | --- | --- |
| bash | running `scripts/signature.sh` | `bash --version` succeeds |
| GitHub CLI (`gh`), authenticated | the user's name and login | `gh auth status` succeeds |

**Hard gate.** If bash, `gh` or the script is missing, or no user is logged in, stop and tell the user how to fix it (`gh auth login`). Do not write the signature by hand, and do not ask for a name or an email address instead.

## Input

- Supported keys:
  - `output_format` (optional, default `markdown`):
    - `JIRA` when the text is for a Jira comment
    - `GitHub` when the text is for a GitHub comment
    - `markdown` for generic markdown
  - `model` (optional): the name of the AI model
  - `editor` (optional): the name of the tool or platform
  - `language` (optional, default `en`): `en` or `no`, for the fixed phrases. Use the language of the text the signature is attached to
  - `basis` (optional): what the text rests on: for measurements the source, time window and n; for code the files and commit; for documents the title and date. It is printed as a `Source:` line above the signature (in the same paragraph for `JIRA`). Always give it when the text contains numbers or claims about how a system behaves.

There is no key for the user. The script reads the name and login of the logged-in `gh` user.

## The source line

- Give `basis` when the text has numbers or claims about how a system behaves. Leave it out for pure code changes and short texts without such content.
- Keep it to one line of about 200 characters at most: the most important sources; the rest belongs in the text itself.
- Never include: internal URLs, secrets, named people (internal or external), patron information, or other sensitive data. Use a system name, file path, time window and count. The script rejects a `basis` that contains a URL (exit 2, no output).

## Output

- `markdown` returns the signature with the user's name linked to their GitHub profile.
- `GitHub` returns the signature with an `@login` mention.
- `JIRA` returns a Jira ADF fragment (a `paragraph`) in italics, with the user's name as plain text. It has no Jira mention, since that would need a per-person Jira id. The fragment is meant to be appended to the `content` of an existing ADF `doc` before it is sent to Jira.

The signature line:

`🤖 Generated with AI by [user] with [model] in [editor]`

The signature contains no email address.

## Running the script

```bash
scripts/signature.sh output_format=<output_format> model="<model>" editor="<editor>" language=<en|no>
```

Always give `output_format`, `model` and `editor`, to the best of your knowledge. Give the rest only when the user asks for it or the text needs it.

The signature from the script is the only AI signature. Do not add the agent's own signature (for example a "Generated with …" line with a link to the session) on top of it.
